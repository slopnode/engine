# Writing s7

Game packages are written in s7 Scheme. This page covers the language first, then how this engine loads and calls it.

Related: [s7 language reference](https://ccrma.stanford.edu/software/snd/snd/s7.html), [Scripting](scripting.md), [Package structure](package-structure.md), [Player](player.md), [Things](things.md).

## What s7 is

[s7](https://ccrma.stanford.edu/software/snd/snd/s7.html) is a small Scheme interpreter meant as an extension language. It is compatible with R5RS and R7RS for ordinary Scheme; as a dialect it is closest to Guile 1.8. The CCRMA page is the full language reference (macros, hash tables, environments, dialect quirks, FFI notes). The rest of this section is only the subset you need day to day.

## Scheme you need

Programs are S-expressions: nested lists in parentheses. A line comment starts with `;`.

```text
; a comment
(+ 1 2)          ; => 3
```

### Values

Numbers, strings, symbols, and booleans are the usual building blocks:

```text
42
3.14
"hello"
'weapon-slot
#t
#f
```

### Style

Prefer a **functional** style: small helpers that take arguments and return values, `let` / `cond` / `and` / `or` for control flow, and new lists instead of in-place edits in the middle of logic.

```text
(define (clamp n lo hi)
  (cond
    ((< n lo) lo)
    ((> n hi) hi)
    (else n)))

(define (damage hp amount)
  (clamp (- hp amount) 0 100))
```

`set!` is available when imperative update is unavoidable — typically top-level package state that must persist across engine hooks (`tick`, `on-action-*`, map handlers). Prefer computing a new value functionally, then `set!` once at the boundary:

```text
(define *health* 100)

(set! *health* (damage *health* 10))
```

`(define (f args) …)` is shorthand for binding a procedure.

### Lists and alists

```text
(define nums (list 10 20 30))
(list-ref nums 1)              ; => 20
(car nums)                     ; => 10
(cdr nums)                     ; => (20 30)

(define entry (cons "attack" '((label . "Attack") (default . "mouse1"))))
(car entry)                    ; => "attack"
(cdr entry)                    ; => ((label . "Attack") (default . "mouse1"))

(define actions (list entry))
(assoc "attack" actions)       ; => ("attack" (label . "Attack") ...)
```

### Control flow

```text
(define (label-for slot)
  (cond
    ((= slot 1) "fist")
    ((= slot 2) "pistol")
    (else "unknown")))

(let ((n 3)
      (m 4))
  (+ n m))                     ; => 7

(and #t #t)                    ; => #t
(or #f "fallback")             ; => "fallback"

(define add1 (lambda (x) (+ x 1)))
(add1 5)                       ; => 6
```

For macros, hash tables, environments, and other dialect features, use the [s7 language reference](https://ccrma.stanford.edu/software/snd/snd/s7.html).

## In this engine

One s7 heap lives for the whole run. Package files use the `.s7` extension. C++ binds engine primitives and calls optional procedures by name. Load order, hooks, and the full binding tables are in [Scripting](scripting.md).

### Where files live

| Location | Role |
|----------|------|
| `scripts/` | Behavior: `init`, `things`, `player`, optional `menus` |
| `data/` | Catalogs: `actions`, `view`, `cli`, … |
| `maps/<name>/things.s7` | Map instances: poses, paths, handler name strings |

Virtual paths omit the folder and `.s7`: `"player"` loads `scripts/player.s7`, `"actions"` loads `data/actions.s7`. Layout detail: [Package structure](package-structure.md).

### Conventions

- Things and actors are identified by **string ids** (flecs entity names). There is no entity object API in Scheme.
- Keep game state in top-level `(define …)` bindings (and structures you build from lists). Mutate those with `set!` only when a hook must update persistent state; keep helpers pure where you can.
- Engine hooks are procedures with **exact names**. If a name is missing, the engine skips it.

### Hooks by name

```text
(define (prepare-first-person player-id)
  (fp-clear-socket "weapon")
  (fp-attach-geo "weapon" "fp/stub" 0.22 -0.18 0.42 0.08 0.08 0.35))

(define (on-action-attack)
  (play-sound "weapons/fire" 0.8))

(define (tick dt)
  (if (action-down? "attack")
      (play-sound "weapons/fire" 0.5)
      #f))

(define (draw-hud)
  (hud-anchor 'top-left)
  (hud-text "ready" 8 8 12 1 1 1 1))

(define (on-startup)
  (let ((map-id (startup-arg "map")))
    (if map-id
        (request-map-load map-id "fresh")
        #t)))
```

Package actions declared in `data/actions.s7` become `(on-action-<id>)` press hooks and work with `(action-down?)` / `(action-pressed?)`. The full hook list is in [Scripting](scripting.md#engine-hooks).

### Mini package

Declare an action, attach a weapon on spawn, fire on press, and wire a pickup through a string handler name.

`data/actions.s7`:

```text
(define *package-actions*
  (list (cons "attack" '((label . "Attack") (default . "mouse1")))))
```

`scripts/player.s7`:

```text
(define (prepare-first-person player-id)
  (fp-clear-socket "weapon")
  (fp-attach-geo "weapon" "fp/stub" 0.22 -0.18 0.42 0.08 0.08 0.35))

(define (on-action-attack)
  (play-sound "weapons/fire" 0.8))
```

`scripts/things.s7` (or the same file as player):

```text
(define (on-enter-ammo thing-id other-id)
  (thing-despawn thing-id))
```

`maps/demo/things.s7`:

```text
(prop
  (id "clip-1")
  (at 0 0 4)
  (sprite "items/clip")
  (on-enter "on-enter-ammo")
  (trigger-size 1 1.5 1))
```

The map stores the handler as the string `"on-enter-ammo"`; the package defines `(on-enter-ammo …)`. That string-name wiring is the usual pattern for `on-enter`, `on-exit`, and `on-use`.

Ownership of map instances vs package scripts is spelled out in [Scripting — What belongs where](scripting.md#what-belongs-where).
